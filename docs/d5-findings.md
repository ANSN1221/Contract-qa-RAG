## 三、四个发现

### 1. 当前默认权重比超过压制阈值（两轮复现）

Q06「货款分几次结清」的实证：

| 环节 | 答案条款 DOC002-C0006 的名次 |
|---|---|
| BM25 单独 | 前 20 条内完全没有 |
| 向量单独 | 第 1 名 |
| 融合 1.0 / 0.5 | **第 21 名** |
| 融合 1.0 / 1.0 或 0.5 / 1.0 | 第 5 名 |

原因可算：RRF 分数为 `weight / (k + rank)`，k=60。向量第 1 名得分 `0.5/61 = 0.0082`，BM25 第 20 名得分 `1.0/80 = 0.0125`。**BM25 的长尾压过了向量的头部。** 阈值：权重比超过 `(60+20)/(60+1) ≈ 1.31` 必然发生，当前 2.0 超标。

### 2. rerank 三轮均无召回增益

- C 组与 D 组三轮全部同分（90/90、80/80、85/85）。
- rerank 只重排候选池内条款，救不回池外条款。
- Q10、Q23 等题有排序提升（第 3 → 第 1），但 Recall@5 不变。

结论：瓶颈在召回与切分，不在排序。保持默认关闭。

### 3. 剩余边界题：同构表格条款（Q20、Q24）

切分规整后仍全灭的两题：

| 题 | 答案条款 | 现状 |
|---|---|---|
| Q24 疫苗投标要交保证金吗 | DOC005-C0009-6、C0012-5 | BM25 第 18 / 第 16 名，向量前 20 没有 |
| Q20 评标委员会几个人 | DOC003-C0011-4 | 两路前 20 都没有 |

根因：招标文件切分后产生大量 440–500 字的**同构条款**（都是「条款号 条款名称 编列内容」表格式段落）。答案条款与几十个兄弟条款几乎同构，只有中间一行字不同，向量与 BM25 都无法定位。字段级结构化抽取（把「3.5 投标保证金」切成独立字段）才能解决，属于后续里程碑，不是检索参数能调的。

### 4. 20 题样本，方向性结论稳定

三轮数据（10 题、20 题规整前、20 题规整后）一致：

- 向量检索稳定强于关键词，与 D3 时期「投标保证金」类术语题的结论相反——差异来自题库构成。
- 权重 1:1 或 0.5:1 稳定优于 1.0/0.5（100 vs 90；85 vs 80；90 vs 85）。
- rerank 三轮零增益。

## 四、已修正

1. **Q01 出题锚点错误。** 原问法含「垃圾中转站」，该词只在合同首页条款出现，答案条款不含。已改问法，四组均命中第 1 名。
2. **切分盲区。** 只设上限不设下限、超长条款不切碎，导致 35% 条款超过 500 字、短条款永远检索不到。已规整（见第二节），并重写 30 题标注的 `relevant_clause_ids`（旧 id 全部通过文本匹配重映射，逐题人工核对）。

## 五、建议（按优先级）

| 项 | 建议 | 依据 |
|---|---|---|
| 默认权重 | 改为 `BM25_WEIGHT=1.0` / `DENSE_WEIGHT=1.0`（**已执行，2026-11-15**） | 三轮数据均优于 2:1，低于压制阈值 1.31 |
| Q20/Q24 | 记入已知边界，留给字段级结构化抽取 | 同构表格条款，检索参数无法解决 |
| rerank | 保持 `RERANK_ENABLED=false` | 三轮零召回增益，每题多 0.46 秒 |
| 种子集 | 扩到 50 题 | 20 题时 1 题 = 5% |

## 六、复现

```bash
uv run python scripts/evaluate_retrieval.py            # A/B/C/D + 权重扫描
uv run python scripts/evaluate_retrieval.py --no-rerank # 只跑 A/B/C，不消耗重排配额
```

向量化每题调用一次，四组共用结果；重排每题一次。30 题整轮约 20 次向量化 + 20 次重排，耗时约半分钟。
